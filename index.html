Setup & Configuration

First things to run on a new machine

git config

Set your identity

Tell Git who you are. This info is attached to every commit you make.

▼
Commands
bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

# Check what you set
git config --list
💡
TipUse --global to apply to all your projects. Skip it to apply to the current project only.
🚀

Init & Clone

Start a new repo or download an existing one

git init

Create a new repository

Turns any folder into a Git repository. Creates a hidden .git folder inside.

▼
Example
bash
mkdir my-project
cd my-project
git init

# Output: Initialized empty Git repository in /my-project/.git/
git clone

Download a repository from GitHub

Copies the entire repo — all files, history, and branches — to your machine.

▼
Example
bash
# Clone into a folder named after the repo
git clone https://github.com/user/repo.git

# Clone into a custom folder name
git clone https://github.com/user/repo.git my-folder
📦

Stage & Commit

Save snapshots of your work

git status

See what changed

Shows which files are modified, staged, or untracked. Run this often!

▼
bash
git status

# On branch main
# Changes not staged for commit:
#   modified:   index.html
# Untracked files:
#   style.css
git add

Stage files for commit

Moves files to the "staging area" — like putting things in a box before sealing it.

▼
bash
# Stage one file
git add index.html

# Stage all changed files
git add .

# Stage specific folder
git add src/
git commit

Save the snapshot

Creates a permanent checkpoint with everything that was staged. Always write a clear message.

▼
bash
# Commit with a message
git commit -m "Add navigation bar to homepage"

# Stage + commit all tracked files in one step
git commit -am "Fix typo in footer"
✅
Good commit messagesUse the format: "Add feature" / "Fix bug" / "Update docs" — start with a verb, keep it under 50 chars.
🌿

Branches

Work on features without touching the main code

git branch

List, create, or delete branches

A branch is like a parallel universe — changes here don't affect other branches until you merge.

▼
bash
# List all local branches (* marks current)
git branch

# Create a new branch
git branch feature-login

# Delete a branch (after merging)
git branch -d feature-login

# Force delete (even if not merged)
git branch -D feature-login
git checkout / git switch

Switch between branches

git switch is the newer, cleaner way. Both work the same.

▼
bash
# Switch to an existing branch
git switch feature-login
git checkout feature-login   # older way

# Create AND switch in one command
git switch -c feature-login
git checkout -b feature-login  # older way

Remote — Push & Pull

Sync your code with GitHub

git remote

Connect to GitHub

"origin" is just the default nickname for your GitHub repo URL.

▼
bash
# Link your local repo to GitHub
git remote add origin https://github.com/user/repo.git

# See your remotes
git remote -v
git push

Upload commits to GitHub

Sends your local commits up to the remote repository.

▼
bash
# Push main branch
git push origin main

# First push of a new branch (sets tracking)
git push -u origin feature-login

# After -u is set, just use:
git push
git pull

Download & merge changes from GitHub

git pull = git fetch + git merge. Gets teammates' changes.

▼
bash
# Pull changes from origin
git pull origin main

# Just fetch (don't merge yet)
git fetch origin

git restore

Undo changes to files — safe & non-destructive

git restore

Throw away unsaved changes in a file

Got messy edits you don't want? Restore brings the file back to its last committed state. No commit is created.

▼
Syntax
bash
git restore <file-name>
Real Examples
bash
# You edited index.html and want to undo all changes
git restore index.html

# Restore all changed files at once
git restore .

# Remove a file from staging (unstage it)
git restore --staged index.html

# Restore a file from a specific commit
git restore --source abc1234 index.html
FlagWhat it does
(no flag)Discards changes in working directory
--stagedUnstages the file (keeps your edits)
--source <hash>Restores from a specific commit
⚠️
WarningRunning git restore <file> permanently deletes unsaved edits. Make sure you don't need those changes!
🔄

git revert

Undo a past commit safely — history stays intact

git revert

Create a new commit that cancels an old one

The safest way to undo a commit. Instead of deleting history, it adds a new "undo" commit on top. Perfect for shared repos.

▼
Syntax
bash
git revert <commit-hash>
Real Example
bash
# 1. Find the commit you want to undo
git log --oneline
abc1234  Add broken feature
def5678  Fix footer bug     ← you want to undo this

# 2. Revert it
git revert def5678

# Git opens editor for commit message (or skip with --no-edit)
git revert def5678 --no-edit

# New commit appears: "Revert 'Fix footer bug'"
✅
Best for teamsUse git revert when you've already pushed commits to GitHub. It never rewrites history, so it won't break your teammates' work.
⏮️

git reset

Move HEAD back in time — rewrites history

git reset

Move your branch pointer to a different commit

Unlike revert, this actually removes commits from history. Use with caution — especially on shared branches.

▼
Syntax
bash
git reset [--soft | --mixed | --hard] <commit-hash>
ModeCommits removed?Staged changes?File edits?
--soft✅ YesKept (staged)Kept
--mixed✅ YesUnstagedKept
--hard✅ YesDeletedDeleted
Real Examples
bash
# --soft: Remove commit, keep changes staged (ready to re-commit)
git reset --soft HEAD~1
# Use case: "I committed too early, let me fix the message"

# --mixed (default): Remove commit, keep changes but unstaged
git reset HEAD~1
# Use case: "I committed wrong files, let me re-stage carefully"

# --hard: Remove commit AND all changes permanently!
git reset --hard HEAD~1
# Use case: "Throw away last commit completely"

# HEAD~1 = one commit before current, HEAD~3 = three commits back
git reset --hard abc1234
🚨
Danger--hard permanently destroys your changes. Never use it on commits already pushed to a shared GitHub branch.
📜

Log & History

Browse your commit history

git log

See all past commits

Shows who committed what and when. Use --oneline for a compact view.

▼
bash
# Full log
git log

# Compact one-line view
git log --oneline

# Visual branch graph
git log --oneline --graph --all

# See what changed in last 3 commits
git log -p -3

abc1234  (HEAD -> main) Add login page
def5678  Fix footer layout
ghi9012  Initial commit

Stash

Temporarily shelve work to switch tasks

git stash

Save changes without committing

Like putting your work in a drawer so you can pull from main and fix a bug, then come back.

▼
bash
# Save current changes to stash
git stash

# Save with a label
git stash push -m "half-done login form"

# List all stashes
git stash list

# Bring stash back and remove it from stash list
git stash pop

# Bring stash back but keep it in the list
git stash apply
🔀

Merge & Rebase

Combine branches together

git merge

Combine another branch into yours

The most common way to bring a feature branch into main. Creates a merge commit.

▼
bash
# 1. Switch to main (target branch)
git switch main

# 2. Merge the feature branch in
git merge feature-login

# If conflicts appear, fix them, then:
git add .
git commit -m "Merge feature-login"
git rebase

Replay commits on top of another branch

Keeps a linear, cleaner history. Use when you want your feature to look like it was built on the latest main.

▼
bash
# On your feature branch, rebase onto main
git switch feature-login
git rebase main
⚠️
CautionNever rebase branches that others are working on — it rewrites history and can cause problems for teammates.
🏷️

Tags

Mark important versions like v1.0

git tag

Create version markers

Tags point to a specific commit permanently — perfect for releases like v1.0.0, v2.1.3.

▼
bash
# List all tags
git tag

# Create a lightweight tag
git tag v1.0.0

# Create an annotated tag (with message)
git tag -a v1.0.0 -m "First stable release"

# Push tag to GitHub
git push origin v1.0.0

# Push all tags at once
git push --tags

Setup & Configuration

First things to run on a new machine

git config

Set your identity

Tell Git who you are. This info is attached to every commit you make.

▼
Commands
bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

# Check what you set
git config --list
💡
TipUse --global to apply to all your projects. Skip it to apply to the current project only.
Advanced — set default editor & branch name
bash
git config --global core.editor "code --wait"
git config --global init.defaultBranch main

Init & Clone

Start a new repo or download an existing one

git init

Create a new repository

Turns any folder into a Git repository. Creates a hidden .git folder inside.

▼
bash
mkdir my-project
cd my-project
git init
# Initialized empty Git repository in /my-project/.git/
git clone

Download a repository from GitHub

Copies the entire repo — all files, history, and branches — to your machine.

▼
bash
# Clone into default folder
git clone https://github.com/user/repo.git

# Clone into custom folder name
git clone https://github.com/user/repo.git my-folder
advanced
# Shallow clone (faster, no full history)
git clone --depth 1 https://github.com/user/repo.git

# Clone single branch
git clone -b main --single-branch https://github.com/user/repo.git

Stage & Commit

Save snapshots of your work

🔥 Most viewed
git status

See what changed

Shows which files are modified, staged, or untracked. Run this often!

▼
bash
git status
# On branch main
# Changes not staged for commit:
#   modified:   index.html
# Untracked files:
#   style.css
git add

Stage files for commit

Moves files to the staging area — like putting things in a box before sealing it.

▼
bash
git add index.html  # Stage one file
git add .            # Stage all changed files
git add src/         # Stage specific folder
advanced
# Stage parts of a file interactively
git add -p index.html
git commit

Save the snapshot

Creates a permanent checkpoint with everything that was staged.

▼
bash
git commit -m "Add navigation bar"
git commit -am "Fix typo in footer"
✅
Good commit messagesFormat: "Add feature" / "Fix bug" / "Update docs" — start with verb, under 50 chars.
advanced
# Amend last commit (before push!)
git commit --amend -m "Corrected message"

# Empty commit (useful for CI triggers)
git commit --allow-empty -m "trigger deploy"
🌿

Branches

Work on features without touching main code

git branch

List, create, or delete branches

A branch is like a parallel universe — changes don't affect other branches until you merge.

▼
bash
git branch                          # List local branches
git branch feature-login            # Create branch
git branch -d feature-login         # Delete (safe)
git branch -D feature-login         # Force delete
advanced
git branch -a                       # List all (local + remote)
git branch -m old-name new-name     # Rename branch
git branch --merged                  # Show merged branches
git checkout / git switch

Switch between branches

git switch is the newer, cleaner way. Both work the same.

▼
bash
git switch feature-login
git switch -c feature-login  # Create + switch
git checkout -b feature-login # older way

Remote — Push & Pull

Sync your code with GitHub

git remote

Connect to GitHub

"origin" is the default nickname for your GitHub repo URL.

▼
bash
git remote add origin https://github.com/user/repo.git
git remote -v   # See your remotes
git push

Upload commits to GitHub

Sends your local commits up to the remote repository.

▼
bash
git push origin main
git push -u origin feature-login  # sets tracking
git push                              # after -u is set
git pull

Download & merge changes from GitHub

git pull = git fetch + git merge. Gets teammates' changes.

▼
bash
git pull origin main
git fetch origin  # just fetch, don't merge yet
↩️

git restore

Undo changes to files — safe & non-destructive

git restore

Throw away unsaved changes in a file

Restore brings the file back to its last committed state. No commit created.

▼
bash
git restore index.html              # discard changes
git restore .                     # restore all files
git restore --staged index.html   # unstage file
git restore --source abc1234 index.html
⚠️
Warninggit restore permanently deletes unsaved edits!
🔄

git revert

Undo a past commit safely — history stays intact

git revert

Create a new commit that cancels an old one

The safest way to undo — adds an "undo" commit on top. Perfect for shared repos.

▼
bash
git log --oneline
abc1234  Add broken feature
def5678  Fix footer bug  ← undo this

git revert def5678
git revert def5678 --no-edit
✅
Best for teamsNever rewrites history — safe to use after pushing.
⏮️

git reset

Move HEAD back in time — rewrites history

git reset

Move your branch pointer to a different commit

Unlike revert, this removes commits from history. Use with caution on shared branches.

▼
ModeCommits removed?Staged?File edits?
--soft✅ YesKept (staged)Kept
--mixed✅ YesUnstagedKept
--hard✅ YesDeletedDeleted
bash
git reset --soft HEAD~1   # keep changes staged
git reset HEAD~1          # keep but unstage
git reset --hard HEAD~1   # ⚠ delete everything
git reset --hard abc1234  # go to specific commit
🚨
Danger--hard permanently destroys changes. Never use on pushed shared branches.
📜

Log & History

Browse your commit history

git log

See all past commits

Shows who committed what and when. Use --oneline for compact view.

▼
bash
git log                       # full log
git log --oneline             # compact view
git log --oneline --graph --all # visual tree
git log -p -3                  # last 3 with diffs
advanced
# Search commits by message keyword
git log --grep="login"

# Show commits by author
git log --author="Kazim"

# Custom format
git log --format="%h %s %an"
🗄️

Stash

Temporarily shelve work to switch tasks

git stash

Save changes without committing

Like putting your work in a drawer so you can fix a bug, then come back.

▼
bash
git stash
git stash push -m "half-done login"
git stash list
git stash pop    # bring back + remove
git stash apply  # bring back, keep in list
advanced
git stash apply stash@{2}  # apply specific stash
git stash drop stash@{0}   # delete a stash
git stash clear             # delete all stashes
git stash branch feature   # create branch from stash
🔀

Merge & Rebase

Combine branches together

git merge

Combine another branch into yours

The most common way to bring a feature branch into main. Creates a merge commit.

▼
bash
git switch main
git merge feature-login
# If conflicts, fix then:
git add . && git commit -m "Merge feature-login"
advanced
git merge --squash feature  # squash all commits into one
git merge --no-ff feature    # always create merge commit
git merge --abort             # abort mid-conflict
git rebase

Replay commits on top of another branch

Keeps a linear, cleaner history.

▼
bash
git switch feature-login
git rebase main
advanced
git rebase -i HEAD~3  # interactive: squash/edit/reorder
git rebase --abort    # abort rebase
git rebase --continue # continue after resolving conflict
⚠️
CautionNever rebase branches others are working on — rewrites history!
🏷️

Tags

Mark important versions like v1.0

git tag

Create version markers

Tags point to a specific commit permanently — perfect for releases like v1.0.0.

▼
bash
git tag                                       # list tags
git tag v1.0.0                               # lightweight
git tag -a v1.0.0 -m "First stable release"  # annotated
git push origin v1.0.0
git push --tags                              # push all
